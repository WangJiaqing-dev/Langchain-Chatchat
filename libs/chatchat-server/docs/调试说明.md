# Chatchat 调试说明

## 1. 用 Cursor / VS Code 断点调试

**先确保依赖装在项目虚拟环境里**（否则会报 `No module named uvicorn` 等）：

```bash
cd libs/chatchat-server
poetry install
```

Poetry 会在当前目录生成 `.venv`，launch.json 已指定使用 `.venv/Scripts/python.exe`（Windows）运行。若你在 Mac/Linux，需把 launch.json 里的 `Scripts/python.exe` 改成 `bin/python`。

项目已配置 `.vscode/launch.json`，在 IDE 中可按 F5 或从“运行和调试”选择：

- **Chatchat: API Server**：只启动 API 服务（7861），带 `--reload`，改代码后自动重载。
- **Chatchat: API Server (no reload)**：同上但不重载，断点更稳定。
- **Chatchat: CLI (e.g. start --api)**：用 `chatchat start --api` 启动（多进程，断点只在主进程生效）。

**使用前：**

1. 在“运行和调试”里选 **Chatchat: API Server**。
2. 在需要停住的地方打断点（如 `kb_routes.py`、`kb_chat.py`）。
3. F5 启动，用浏览器或另一终端访问 8301 WebUI，或直接请求 `http://127.0.0.1:7861/docs` 触发接口。

**注意：** 若数据目录或配置不在 `libs/chatchat-server`，可在 launch.json 里改 `CHATCHAT_ROOT` 或 `cwd`。

---

## 2. 开启详细日志

在 `basic_settings.yaml` 中设置：

```yaml
log_verbose: true
```

会输出更详细的运行日志，便于排查问题。

---

## 3. 查看接口收到的 POST 参数

在以下接口入口已加请求参数日志（INFO 级别）：

- `POST /knowledge_base/{mode}/{param}/chat/completions`（知识库对话）
- `POST /chat/chat/completions`（统一 chat）

日志中会看到类似：

```text
[POST /knowledge_base/local_kb/Netpropto/chat/completions] request params: {...}
```

确保未把日志级别调成 WARNING/ERROR，否则看不到 INFO。

---

## 4. 只开 API 方便调试

不启动 WebUI，只起 API，方便用 curl / Postman / 前端单独调接口：

```bash
cd libs/chatchat-server
set CHATCHAT_ROOT=%cd%
chatchat start --api
```

然后用浏览器打开 http://127.0.0.1:7861/docs 调用接口；WebUI 需要时再另开一个终端 `chatchat start -w`。

---

## 5. 源码/开发环境

从源码跑并安装依赖（Poetry）：

```bash
cd libs/chatchat-server
poetry install --with lint,test -E xinference
```

将 IDE 的“源代码根目录”或 Python 解释器设为 `libs/chatchat-server`，可正确跳转和断点。

---

## 6. 常见问题

- **断点不命中**：确认选的是“Chatchat: API Server”且请求确实打到 7861 端口的 API；若用 `chatchat start -a`，API 在子进程，需用上面“只开 API”的方式或直接 uvicorn 启动才能断点。
- **找不到配置/数据**：检查 `CHATCHAT_ROOT` 是否指向包含 `basic_settings.yaml`、`kb_settings.yaml`、`data` 的目录（一般为 `libs/chatchat-server`）。
- **修改 prompt/配置不生效**：改 `prompt_settings.yaml` 或 `*_settings.yaml` 后需重启服务；若用 `--reload` 只对 `.py` 文件重载，改 yaml 后也要重启。
